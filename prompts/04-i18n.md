# 04 · Multi-language (i18n)

Status: done

## Context

All UI copy is hardcoded Traditional Chinese: about 10 strings across `src/app/index.tsx`, `src/components/listing-card.tsx`, and `ui/alert.tsx` / `ui/text-field.tsx`, the category labels, and the mock listing titles and locations in `src/data/listings.ts`. Staylo serves international guests, so the app should speak their language, follow the device language by default, and let users override it in the app.

Decisions from the question round:
- Languages: **zh-TW** (default and fallback), **en**, **ja**, **zh-CN**.
- Library: **i18next + react-i18next**, with **expo-localization** for detecting the device language.
- Selection: follow the system by default, plus an **in-app language picker**. The choice is saved on the device.
- Content: the mock listing title/location become **per-language fields**, shaped to match future Sanity field-level i18n. The Sanity localization strategy gets its own plan later.

When building, first copy this plan to `prompts/04-i18n.md` (`Status: done`), as the AGENTS.md workflow requires.

## Defaults picked (not asked)

- **New dependencies:** `expo-localization`, `i18next`, `react-i18next`, and `@react-native-async-storage/async-storage`, all installed with `npx expo install`. The language choice is stored with AsyncStorage, not `expo-sqlite/kv-store`, because expo-sqlite on web needs WASM plus COOP/COEP headers, while AsyncStorage uses localStorage on web. All four work in Expo Go.
- **Locale resolution:** the device locale maps to a supported language:
  - `zh-Hant` / `zh-TW` / `zh-HK` / `zh-MO` → zh-TW
  - `zh-Hans` / `zh-CN` / `zh-SG` → zh-CN
  - `ja*` → ja, `en*` → en
  - anything else → zh-TW
- **Prices:** listings are priced in TWD, so every language shows `NT$` + a locale-formatted number (`Intl.NumberFormat(lng)`). Only the "/ night" suffix is translated.
- **Language names** in the picker are endonyms (繁體中文, English, 日本語, 简体中文) and are not translated. "Follow system" is translated and shows the resolved language.
- **Picker UI:** a new route `src/app/language.tsx` presented as a native `formSheet`, not a custom modal (native-slop rule). It's opened by a globe `IconButton` in the home header, next to the dev palette button.
- **Out of scope:** the `/design-system` dev page copy, localizing the app name (it's "Staylo" everywhere), RTL (no RTL languages), and Sanity content.

## Approach

### 1. Install and configure
- `npx expo install expo-localization i18next react-i18next @react-native-async-storage/async-storage`
- `app.json` plugins: add `["expo-localization", { "supportedLocales": ["zh-TW", "en", "ja", "zh-CN"] }]`. This enables the iOS/Android per-app language setting, which only takes effect in a dev/production build; Expo Go ignores it.

### 2. i18n core (`src/i18n/`)
- `locales/zh-TW.ts`: the **source of truth**, a nested `as const` object grouped by screen (`home.*`, `listing.*`, `category.*`, `a11y.*`, `language.*`).
- `locales/en.ts`, `ja.ts`, `zh-CN.ts`: typed `satisfies Translations`, where `Translations` is `zh-TW`'s shape with strings widened. A missing or extra key is a type error.
- `types.ts`: `Language = 'zh-TW' | 'en' | 'ja' | 'zh-CN'`, `LocalizedText = Record<Language, string>`, and a `declare module 'i18next'` `CustomTypeOptions` augmentation so `t('home.searchPlaceholder')` keys are type-checked.
- `resolve.ts`: `resolveDeviceLanguage(locales)` (the mapping above) and `localize(text: LocalizedText, lng)` (falls back to zh-TW).
- `index.ts`: `i18next.use(initReactI18next).init({ resources, lng: resolveDeviceLanguage(getLocales()), fallbackLng: 'zh-TW', interpolation: { escapeValue: false } })`.
- `language-preference.ts`: a `useLanguagePreference()` hook that holds `'system' | Language`. It reads and writes AsyncStorage key `staylo.language`, calls `i18next.changeLanguage`, and while on `'system'` re-resolves from `useLocales()` so OS language changes are picked up.
- `format.ts`: `formatPrice(amount, lng)` → `NT$3,200`.

### 3. Root wiring (`src/app/_layout.tsx`)
- Import `@/i18n` once at the top, next to `@/global.css`.
- Keep the splash screen until **both** the fonts and the stored language preference are loaded, so the first screen never flashes the wrong language. This extends the existing `ready` logic.
- Register `language` in the Stack with `presentation: 'formSheet'`, `sheetAllowedDetents: [0.5]`, and a translated title.

### 4. Replace hardcoded strings
- `src/app/index.tsx`: tagline, search placeholder and its a11y label, empty state, and the a11y labels of the palette and globe buttons. Use `t()` from `useTranslation()`.
- `src/components/listing-card.tsx`: the favorite a11y labels and "/ 晚" → `t()`; the price → `formatPrice`; the title/location → `localize(listing.title, i18n.language)`.
- `ui/alert.tsx` ("關閉") and `ui/text-field.tsx` (show/hide password): their default a11y labels come from `t()`.
- `src/data/listings.ts`: drop `label` from `Category` (labels come from `t('category.<id>')`). `title` and `location` become `LocalizedText`, with en/ja/zh-CN versions for all 6 mock listings. Search matches against the current language's text.

### 5. Language picker (`src/app/language.tsx`)
- Rows: "Follow system (current: …)" plus the 4 endonyms. The selected row has a check `Icon` (tone primary). Tapping a row saves the choice, switches the language, and closes the sheet (`router.back()`).
- Built from the existing `ui/` primitives (`Text`, `Icon`) and tokens only. Pressable rows with `active:` feedback and `accessibilityRole="radio"` / `accessibilityState.checked`.

### 6. Docs
- AGENTS.md: add an **i18n** section:
  - All UI copy goes through `t()`, with keys in `src/i18n/locales/zh-TW.ts` (the source of truth) and the other locales kept type-complete.
  - Content fields use `LocalizedText` + `localize()`.
  - Prices use `formatPrice`.
  - Language names are endonyms.
  - New strings are added to all 4 locales in the same change.
- Plan file `prompts/04-i18n.md`, with `## Result` filled in at the end.

## Verification
- `npx expo lint`, `npx tsc --noEmit`. Plus a temporary type test: deleting a key from `en.ts` must fail tsc.
- `npx expo export --platform ios --platform android --platform web` succeeds.
- `grep -rP '[\x{4e00}-\x{9fff}]' src --exclude-dir=i18n` finds Chinese only in `src/data/listings.ts` (localized content) and `src/app/design-system.tsx` (dev page, out of scope).
- Web, headless Chrome against the dev server with `--lang=en`, `--lang=ja`, `--lang=zh-CN`, `--lang=zh-TW`, and `--lang=fr` (expected to fall back to zh-TW). Screenshot the home screen for each and confirm the copy, category chips, listing titles, and the `NT$` price format.
- Web: open `/language`, pick English, and reload. The choice persists (AsyncStorage → localStorage).
- Device (user, Expo Go): switch languages in the sheet, then set the picker back to "follow system" and change the iPhone language.
- Run `npx expo start --clear` after the change, since new Tailwind classes need a fresh CSS build (AGENTS.md note).

## Result

The app runs in zh-TW, en, ja, and zh-CN. It follows the device language and has an in-app picker at `/language`, opened by the globe button on the home screen.

- Deviation: the preference is a `LanguagePreferenceProvider` + `useLanguagePreference()` (`src/i18n/language-preference.tsx`) instead of a bare hook, because the root layout (which holds the splash screen) and the picker share the state.
- i18next is used through `createInstance()` (`src/i18n/index.ts`). This avoids the default-instance lint warnings, and `initReactI18next` registers it for `useTranslation()`.
- Verified:
  - lint and tsc pass.
  - Removing a key from `en.ts` fails tsc.
  - The ios/android/web export succeeds.
  - Chinese characters outside `src/i18n` remain only in `src/data/listings.ts` (localized content) and `src/app/design-system.tsx` (dev page).
  - Web screenshots with the browser language set to en, ja, zh-CN, zh-TW, and fr (fr falls back to zh-TW) show translated copy, chips, listing titles and locations, `NT$3,200`, and "/ night", "/ 泊", "/ 晚".
  - The `/language` sheet renders with "follow system (current: 日本語)".
- Not verified: tapping a language and the persistence after reload (headless Chrome can't tap), and devices. The user needs to check these in Expo Go.
- Follow-ups:
  - Dark mode made the sheet title unreadable, because React Navigation stayed on its light theme. The root layout now wraps the Stack in `ThemeProvider` (Dark/Default by color scheme), and `screenOptions` sets the header colors from tokens.
  - The language sheet was redesigned as cards. A "Follow system" card shows the resolved language, followed by a 2×2 grid of language cards: the endonym plus the name in the UI language (hidden when they're the same). The selected card gets a coral border and a check. The sheet shows its own title and has detents 0.65 / 1.
